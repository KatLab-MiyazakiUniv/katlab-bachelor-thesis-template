\chapter{考察}\label{cha:Discussion}

本章では、前章の実験結果に基づき、提案プロンプトの有効性、自由プロンプトとの比較、システムの複雑さが与える影響、そしてプロンプト構成要素の寄与について考察する。最後に、本手法の課題と限界について述べる。

\section{提案プロンプトの有効性}
実験結果から、提案プロンプトを用いることで、システム仕様書作成経験のない学生でも一定品質以上の章立てを作成できることが示された。本節では、その有効性について詳述する。

\subsection{品質の安定性とバランス}
提案プロンプトを用いた場合、評価項目間のばらつきが比較的小さく、全体として安定した品質を保っていることが確認された。特にBMP画像分割アプリにおける被験者Bの結果は、9項目中7項目で4.0点以上を獲得しており、評価者からも「バランスが良い」「一番整理されている」との高評価を得ている。
これに対し、人手のみで作成した場合は、BMPで平均スコア3.2$\sim$4.0、電子契約で2.8$\sim$3.8と全体的に低調であり、「章立てが荒い」「不足が多い」といった指摘が共通して見られた。提案手法は、経験不足による考慮漏れや構成の不備を効果的に補完していると言える。

\subsection{構造的整合性の確保}
提案プロンプトを使用した章立ては、構造的整合性（評価項目8）において比較的高い評価を得ている（BMP: 3.6$\sim$4.0点、電子契約: 3.6$\sim$3.8点）。これは、プロンプト内で「ベース章立てテンプレート」を提供し、章・節・項の包含関係の模範を示したことが奏功したと考えられる。
また、同じ提案プロンプトを使用した異なる被験者間（BMPの被験者BとD、電子契約の被験者AとC）の結果を比較しても、一定の品質水準が維持されている。これは、個人の能力に依存せず、プロンプトの力によって一定の成果を引き出せる再現性を示唆している。

\section{自由プロンプトとの比較}
ここでは、提案プロンプトと自由プロンプト（プロンプト指定なし）のアプローチの違いが生成結果に与えた影響を比較する。

\subsection{網羅性と冗長性のトレードオフ}
自由プロンプトは、網羅性（BMP 4.8点、電子契約 4.6点）において最も高い評価を得た。これは、被験者が対話を通じて思いつく限りの機能を列挙させた結果と考えられる。しかし、その一方で「冗長」というネガティブなコメントも複数の評価者から寄せられている。
特にBMP画像分割アプリにおける拡張性の評価では、自由プロンプトが2.8点と極端に低い値を示した。これは、網羅性を追求するあまり、システムの単純な仕様に対して過度に詳細すぎる章立てとなり、かえって将来の変更を困難にする構成になってしまったためと推察される。
提案プロンプトは、網羅性においては自由プロンプトに及ばないものの（BMP 4.2$\sim$4.4点）、人手のみと比較すれば十分に高い数値を達成しており、かつ「冗長」との指摘を受けていない。このことから、提案プロンプトは網羅性と簡潔さのバランスにおいて優れていると言える。

\subsection{独自性について}
独自性（評価項目9）に関しては、自由プロンプトが高い評価を得た（BMP 4.2点、電子契約 4.6点）。自由な対話によって、システム固有の機能について深く掘り下げることができたためである。
一方、提案プロンプトの独自性は3.6$\sim$3.8点に留まった。これは、提供されたベース章立てテンプレートに引きずられ、システム固有の特性を反映しきれなかった可能性を示している。

\section{システムの複雑さによる影響}
実験対象とした2つのシステム（単純なBMP画像分割アプリと、複雑なクラウド型電子契約サービス）の違いによる影響について考察する。

\subsection{システム規模と手法の適合性}
単純なシステムであるBMP画像分割アプリにおいては、提案プロンプトは安定して高品質な章立てを生成できた。しかし、多機能で複雑なクラウド型電子契約サービスにおいては、被験者による品質の差が見られた。
具体的には、電子契約における被験者Aの結果で詳細度が2.8点と低くなり、「粒度が荒い」という指摘を受けた。一方で被験者Cは同じプロンプトで詳細度4.0点を獲得している。
これは、複雑なシステムになるほど、LLMとの対話の中で適切に情報を補足し、深掘りを行うスキルが求められることを示唆している。提案プロンプトは一定のガイドラインを提供するが、システムの複雑さが増すと、それだけで十分な詳細度を確保することが難しくなる場合がある。

\subsection{自由プロンプトの挙動}
自由プロンプトは、複雑なシステムである電子契約サービスにおいて、全体的に高いスコア（詳細度4.8点など）を記録した。複雑なシステムの場合、機能が多岐にわたるため、自由な対話によって多くの章を生成するアプローチが、結果的に「漏れのない」詳細な仕様書構成につながりやすい可能性がある。ただし、前述の通り「冗長である」という課題は残る。

\section{プロンプト構成要素の評価}
提案プロンプトに含まれる各要素が、品質向上にどのように寄与したか考察する。

\subsection{効果的な要素}
\begin{itemize}
    \item \textbf{ベース章立てテンプレート}: 前述の通り、構造的整合性の維持に大きく貢献した。初心者がゼロから構成を考える負担を減らし、論理的な枠組みを提供した。
    \item \textbf{システム仕様書の定義}: 「目的」「対象読者」「記述スタイル」を明記したことで、可読性と適合性の向上に寄与したと考えられる。「バランスが良い」という評価は、この定義によって記述の方向性が定まった結果と言える。
    \item \textbf{出力指示の明確さ}: 「マークダウンの番号付きリスト」等の形式指定により、論理的で見やすい出力が得られた。
\end{itemize}

\subsection{改善が必要な要素}
一方で、以下の点には改善の余地がある。
\begin{itemize}
    \item \textbf{独自性の不足}: ベーステンプレートの影響が強く出過ぎてしまう傾向がある。「ベースはあくまで参考」という注釈だけでは不十分であり、システム固有の機能を章立てに反映させるための、より強い誘導やステップが必要である。
    \item \textbf{粒度の調整}: 「画面レイアウトと操作フローのみ含める」という粒度指定を行ったが、複雑なシステムではこれでは不十分な場合があった。システムの規模や複雑さに応じて、記述粒度を動的に調整するような指示の工夫が求められる。
\end{itemize}

\section{課題と限界}
本実験を通じて明らかになった課題と限界についてまとめる。

第一に、\textbf{独自性とテンプレート依存のジレンマ}である。ベーステンプレートは構造の安定化に寄与する反面、創造的で独自性のある章立てを阻害する要因にもなり得る。テンプレートの利点を活かしつつ、システム固有の要素を柔軟に取り入れるためのプロンプト改良が必要である。

第二に、\textbf{複雑なシステムへの対応力}である。単純なアプリでは十分な性能を発揮したが、大規模システムに対しては詳細度が不足する場合があった。これに対応するためには、単一のプロンプトで全てを生成するのではなく、機能ごとに分割して章立てを生成するなど、段階的なアプローチの検討が必要かもしれない。

第三に、\textbf{被験者の対話スキルへの依存}である。提案手法は自動化を意図しているものの、実際にはLLMとの対話プロセスにおいて人間が介在する余地があり、その結果に個人差が生じた。より再現性を高めるためには、対話プロセス自体のガイドライン化や、Few-shotプロンプトの拡充などが考えられる。


まずは、単純なプロンプトで、LLMの膨大な学習データを活かし、網羅性を高めた章立て案を作成させ、そこから、型に嵌めていく方が良いのかもしれない。

本章では、論文執筆における章立てとセクション構成について説明する。

% \section{章の構成}

論文は複数の章で構成される。各章は \verb|\chapter{}| コマンドで定義する。

% \subsection{章番号の自動付与}

LaTeX では章番号が自動的に付与される。
例えば、本章は第\ref{cha:Evaluation}章である。

% \subsection{章のラベル付け}

各章には \verb|\label{}| を付けることで、他の箇所から参照できる。
これにより、章番号が変更されても参照が自動的に更新される。

% \section{セクションの構成}

各章は複数のセクションで構成される。

% \subsection{セクションの階層}

LaTeX では以下の階層構造が使用できる：

\begin{enumerate}
  \item \verb|\chapter{}|: 章 (1, 2, 3, ...)
  \item \verb|\section{}|: 節 (1.1, 1.2, 1.3, ...)
  % \item \verb|\subsection{}|: 小節 (1.1.1, 1.1.2, 1.1.3, ...)
  \item \verb|\subsubsection{}|: 小小節 (1.1.1.1, 1.1.1.2, 1.1.1.3, ...)
\end{enumerate}

% \subsection{適切な階層の選択}

論文の構成を考える際は、以下の点に注意する：

\begin{itemize}
  \item 階層が深くなりすぎないようにする（通常は subsection まで）
  \item 各セクションには適切な量の内容を含める
  \item セクションの粒度を統一する
\end{itemize}

% \section{論文の一般的な構成}

片山徹郎研究室で主に使われてきた、修士論文の一般的な構成は以下の通りである：

\begin{enumerate}
  \item はじめに
  \item 研究の準備（使用ツール、ライブラリの紹介）
  \item 機能
  \item 実装
  \item 適用例
  \item 考察
  \item おわりに（まとめと今後の課題）
\end{enumerate}

この構成が全てではなく、研究内容に合わせて適宜変更されることが多い。
例えば、卒業論文で開発したツールの拡張を行う場合は、拡張した箇所の説明を追加することが多い。
詳細な構成などは、片山研の \verb|graduate| フォルダにある論文を参考にすると良い。
